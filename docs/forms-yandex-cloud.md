# Формы сайта через Yandex Cloud Functions и Postbox

Сайт остается полностью статическим. Все формы отправляют одинаковый JSON-запрос в одну Yandex Cloud Function. Функция проверяет данные и отправляет письмо через Yandex Cloud Postbox на адрес заказчика. Сервер, Telegram-бот и база данных для этого не нужны.

## Что уже реализовано

- формы «Заказать звонок», «Скачать каталог», «Оставить заявку», «Получить проект» и «Рассчитать стоимость»;
- проверка имени, телефона, email и согласия в браузере;
- состояние отправки, сообщение об успехе и понятная ошибка с телефоном компании;
- скрытое поле-ловушка для простых спам-ботов;
- серверная проверка допустимого домена, размера и структуры запроса;
- отсутствие персональных данных в журнале функции;
- отправка текстовой и HTML-версии заявки через Postbox;
- авторизация в Postbox временным IAM-токеном сервисного аккаунта функции.

Код функции находится в `serverless/forms`. Он не требует сторонних npm-пакетов.

## 1. Создать адрес в Yandex Cloud Postbox

1. В каталоге Yandex Cloud откройте **Cloud Postbox → Создать адрес**.
2. Укажите домен `derevo18.com`.
3. Для DKIM выберите простой способ настройки.
4. При необходимости ограничьте список отправителей адресом `forms@derevo18.com`.
5. Создайте адрес и скопируйте предложенные сервисом DNS-записи.
6. Добавьте эти записи в DNS-зону домена у текущего регистратора или в Yandex Cloud DNS.
7. Дождитесь, когда Postbox подтвердит владение доменом.

Postbox отправляет письма только с подтвержденного домена. Помимо обязательной DKIM-записи рекомендуется настроить SPF и DMARC — это снижает вероятность попадания заявок в спам.

Переносить сайт или DNS-зону в Yandex Cloud для подтверждения домена необязательно: нужные записи можно добавить у текущего DNS-провайдера.

## 2. Создать сервисный аккаунт

1. В том же каталоге Yandex Cloud создайте сервисный аккаунт, например `derevo18-forms`.
2. Назначьте ему роль `postbox.sender` на каталог.

Не создавайте статический ключ доступа. Cloud Functions передает обработчику временный IAM-токен привязанного сервисного аккаунта, а код функции использует его только для вызова Postbox API.

## 3. Создать Cloud Function

1. Откройте **Cloud Functions → Создать функцию**.
2. Создайте версию со средой Node.js не ниже 18.
3. Загрузите два файла из `serverless/forms`: `index.js` и `package.json`.
4. Укажите точку входа `index.handler`.
5. Для начала достаточно 128 МБ памяти и тайм-аута 10 секунд.
6. Обязательно выберите сервисный аккаунт `derevo18-forms`. Без него функция не получит IAM-токен и не сможет вызвать Postbox.
7. Добавьте переменные окружения:
   - `POSTBOX_FROM` — подтвержденный отправитель, например `forms@derevo18.com`;
   - `POSTBOX_TO` — адрес заказчика, например `59286@mail.ru`;
   - `ALLOWED_ORIGINS` — допустимые адреса сайта.

В `POSTBOX_TO` можно указать несколько получателей через запятую, но не более десяти.

До отключения тестового стенда `ALLOWED_ORIGINS` может выглядеть так:

```text
https://derevo18.com,https://www.derevo18.com,https://derevo18-astro.workers.dev
```

Адреса разделяются запятыми без завершающего `/`. После отключения Cloudflare удалите тестовый адрес и создайте новую версию функции.

## 4. Разрешить HTTPS-вызов

Сделайте функцию публичной для вызова. Код функции самостоятельно принимает только `POST` и `OPTIONS`, проверяет заголовок `Origin` и не возвращает персональные данные.

Скопируйте HTTPS-адрес вида:

```text
https://functions.yandexcloud.net/<function-id>
```

Для текущего небольшого сайта отдельный API Gateway не нужен. Его можно добавить позднее, если понадобятся собственный API-домен, централизованные квоты или несколько функций.

## 5. Проверить функцию отдельно от сайта

Пример проверки из PowerShell:

```powershell
$requestBody = @{
  formId = "estimate"
  name = "Тест"
  phone = "+7 (919) 916-80-22"
  consent = $true
  page = "https://derevo18.com/"
  website = ""
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "https://functions.yandexcloud.net/<function-id>" `
  -Headers @{ Origin = "https://derevo18.com" } `
  -ContentType "application/json" `
  -Body $requestBody
```

Ожидаемый ответ — `{ "ok": true }`, после чего письмо должно прийти на адрес из `POSTBOX_TO`. В письме будут название формы, имя, телефон, email при его наличии, исходная страница и время заявки.

Если функция вернула `502`, проверьте:

- привязан ли к версии функции сервисный аккаунт;
- есть ли у него роль `postbox.sender`;
- подтвержден ли домен в Postbox;
- разрешен ли адрес из `POSTBOX_FROM`;
- заданы ли все три переменные окружения.

## 6. Подключить сайт

1. В GitHub откройте **Settings → Secrets and variables → Actions → Variables**.
2. Создайте repository variable `PUBLIC_FORMS_ENDPOINT`.
3. Вставьте публичный HTTPS-адрес функции.
4. Запустите тестовую или production-сборку сайта.

`PUBLIC_FORMS_ENDPOINT` не является секретом: браузеру в любом случае нужен этот адрес для отправки запроса. Секретные ключи Postbox сайту не требуются.

Если переменная не настроена, пользователь увидит сообщение, что отправка пока недоступна, и номер телефона компании.

## Защита и ограничения

Текущая реализация отсекает простых ботов скрытым полем, ограничивает размер данных и разрешенные браузерные домены. Заголовок `Origin` и CORS не являются полноценной защитой от целевых автоматических запросов.

Если после запуска появится спам, следующим шагом следует подключить Yandex SmartCaptcha: публичный ключ добавляется на сайт, секретный — в настройки функции, а токен проверяется до отправки письма.

Заявки сейчас не записываются в базу данных. Если Postbox временно недоступен, функция вернет ошибку, и сайт предложит посетителю повторить отправку или позвонить. Если понадобится гарантированная история заявок, функцию можно дополнить записью в Serverless YDB.

До публикации форм на основном домене необходимо получить у заказчика текст политики обработки персональных данных и заменить текущую страницу-заглушку реальной юридической страницей.
